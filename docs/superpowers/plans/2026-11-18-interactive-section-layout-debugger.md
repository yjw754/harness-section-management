# Interactive Section Layout Debugger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local HTML tool for editing and solving circular Position Point layout cases with the real Stage 2 solver.

**Architecture:** An opt-in WebAssembly target exposes a stateless, native-testable circular solver adapter. The page owns the editable draft, validates imports, and displays the last successful solver result separately from the draft.

**Tech Stack:** C++14 (C++17 only for the Embind wrapper), CMake, Emscripten, JavaScript ES modules, SVG, GoogleTest and Python Playwright for Chromium.

**Spec:** `docs/superpowers/specs/2026-11-18-interactive-section-layout-debugger-design.md` (the schema and field semantics are normative).

## Global Constraints

- Internal use over local HTTP (`127.0.0.1`); no public hosting, service/backend, persistence, JS solver, or new production dependency. No git commit, push, or merge without user authorization; leave manual HTML review to the user.
- Stage 2 algorithm version 1 with existing default solve settings. `HRN_BUILD_INTERACTIVE_DEBUG_TOOL` defaults to `OFF` and requires Emscripten and `HRN_MAX_STAGE` of `2` or `3`. Native tests and the existing static report remain independently usable.
- `schemaVersion: 1`; both side Roots and member Sections use `shape: {kind: "circular", radius}`. There are always two side Root containers; each side can have 0, 1 or N top-level members (`parentId: null`).
- V1 edits radius directly and has no shape selector or non-circular solve/draw path. Once core support exists, rectangular `longSide`/`shortSide` (full lengths) and elliptical `semiMajorAxis`/`semiMinorAxis` (half lengths) are direct page inputs, not an import workflow. Keep shape controls and SVG geometry separate from tree/mapping data so those paths can be extended; do not add unavailable controls or a mixed-shape promise.
- Text/numeric edits debounce at 300 ms; structural edits calculate after the draft is consistent. Same-position is the default for new relations and all supplied review fixtures use it. The internal editor may explicitly switch a relation to ordinary, per the debugger spec; existing matrix reports stay untouched.
- Compile and solve a bilateral case in WASM before building the full editor. If this requires invasive core changes, stop with the actual build/link/runtime evidence for design reconsideration. Emscripten and Chromium/Playwright are developer prerequisites, not downloaded from the native build.

## Review Focus

- A pasted rectangular member or elliptical Root is rejected atomically; a previous draft, selection and solved SVG never change (Task 4: `test_rejected_import_does_not_change_the_case`).
- Retyping a mapped Section ID must not orphan references, and reordering/duplicate display labels must not exchange result identities (Tasks 2/3: `StableIdsAreNotLabelsOrIndices`, `test_rename_updates_references_atomically`).
- An input that parses but cannot be packed must not draw its failed dimensions or end up showing a successful status with stale geometry (Task 4: `test_failure_keeps_only_the_last_successful_geometry`).
- A side change with incoming or outgoing references cannot move only part of a tree; deleting a parent clears only its direct child links and incident mappings (Task 3: `test_referenced_side_move_and_delete`).
- A blank numeric field, imported numeric string, or overflow is not zero and cannot launch a supposedly valid solve (Tasks 1/3/4: `test_wasm_boundary`, `test_numeric_edits_debounce`, `test_rejected_import_does_not_change_the_case`).

### Task 1: Prove the actual C++ solver runs in the browser

**Files:** Modify `CMakeLists.txt`; create `demo/interactive/HrnInteractiveCase.{h,cpp}`, `demo/interactive/HrnInteractiveBindings.cpp`, `tests/browser/interactive_debugger_smoke_test.py`.

**Interfaces:** `hrn::solveInteractiveCase(const HrnInteractiveCaseDefinition&) -> HrnInteractiveCaseResult`; emitted JS ES module has a default async factory whose module exposes `solveCase(caseObject) -> resultObject`. Both this test and the editor use that same entry point. Root and section fields mirror the spec; missing required JS fields and fields of the wrong primitive type return validation errors without Embind coercion.

- [ ] **Add a failing WASM test.** In `test_wasm_boundary`, load `hrn_interactive_solver.js` over a loopback test server serving `build-wasm/interactive`. Pass the spec's exact bilateral case (20/20 Roots; radius 8 members `p-main`, `n-main`; one same-position link). Assert `valid && solved`, both centers are `(0,0)` within `1e-9`, solved member radii equal 8, and the relation carries the original IDs and `samePosition: true`. Repeat with `roots.positive.shape.radius: "20"` and `Infinity`; expect `valid == false`, a field path and no geometry.
- [ ] **Run red.** With activated SDK, Python Playwright and Chromium, run `python3 tests/browser/interactive_debugger_smoke_test.py --directory build-wasm/interactive`; expect failure loading the not-yet-built module. The test takes `--directory`, starts a loopback server on an ephemeral port, and stops it on exit. Use the repository's `tests/browser/` unittest style.
- [ ] **Build the smallest end-to-end slice.** Add the opt-in guard (`use emcmake` error on native; Stage 1 error under Emscripten). Reuse the single `hrn_visual_report` library under the opt-in target without enabling its demo/export target. In `HrnInteractiveCase.h` declare `HrnInteractiveShape` (`std::string kind`, `double radius`), `HrnInteractiveSectionOptions` (shape, rotation, spacing, auto-resize), `HrnInteractiveSectionDefinition` (ID, label, side, parent ID, options), `HrnInteractiveRelation` (endpoint IDs, same-position), and `HrnInteractiveCaseDefinition` (`schema_version`, `modeling_tolerance`, `Matrix4D`, two Root options, members, relations). Document native empty parent ID as the sentinel for JSON `null`; binding rejects an empty string parent ID. Use typed native result structs translated into the JS output contract below. Keep the native adapter independent of Embind; stage the minimal model assembly/read path now and complete native validation in Task 2. The public JS boundary takes only strictly typed v1 fields and must not reach the solver on malformed input, even during the spike.
- [ ] **Run green.** `emcmake cmake -S . -B build-wasm -DHRN_MAX_STAGE=2 -DHRN_BUILD_TESTS=OFF -DHRN_BUILD_INTERACTIVE_DEBUG_TOOL=ON`; `cmake --build build-wasm --parallel`; repeat the smoke test. Expect the emitted `hrn_interactive_solver.js`/`.wasm` to load and solve with no native-core edits. If the SDK is absent, record the prerequisite before attempting this gate; do not substitute a mock for the passing WASM test.

**JS output contract for all tasks:** `{valid, solved, errors, status, diagnostics, roots, nodes, relations, counters?}`. `errors` is `Array<{path, message}>`, `status` is `invalid`, `unsolved` or `solved`, and `diagnostics` is `string[]`. Roots keyed by `positive`/`negative` expose `inputShape` and optional `solvedShape`. Nodes expose `id`, `label`, `side`, nullable `parentId`, `depth`, `inputShape`, `inputRotation`; if solved they also have `solvedShape`, `solvedRotation` and `center: {x,y}`. Relations use the input field names. Optional `counters` holds per-side `candidateCount` and `iterationsUsed`. On invalid data return errors with `roots: {}`, `nodes: []` and `relations: []`. On valid but unsolved data, return draft metadata/diagnostics with all solved fields omitted. A browser-side validation error uses the same field error shape.

### Task 3: Make a local, directly editable case page

**Files:** Create `demo/interactive/{index.html,app.css,app.js}` and `tests/browser/interactive_debugger_browser_test.py`; modify `CMakeLists.txt` to copy assets to `build-wasm/interactive` on every relevant incremental build.

**Interfaces:** `validateCaseDraft(draft) -> FieldError[]`, `editCaseDraft(draft, action) -> {draft, warning?, error?}` and async `startDebugger({solveCase})` in `app.js`; `solveCase` uses Task 1's result. Use section edit actions keyed by original stable ID, not a display label. Use an exported `startDebugger` accepting a solver function so the debounce/editor component tests can count calls; normal `index.html` boot always uses the WASM module. Use stable test IDs (`root-positive-radius`, `auto-calculate`, `calculate`, `section-editor`, `relation-editor`, `status`) and row metadata `data-section-id`.

- [ ] **Add failing editor tests.** `test_numeric_edits_debounce`: with a fake clock/counting solver, two radius edits within 300 ms make one call 300 ms after the last edit; manual **计算** cancels a pending timer and calls once; disabling auto-calculate leaves changes editable; a blank number produces an error and no solver call. Verify text typing retains focus. `test_rename_updates_references_atomically`: renaming a mapped parent rewrites all child/endpoint references, while renaming to an existing ID leaves the references and accepted ID unchanged and reports an error. `test_referenced_side_move_and_delete`: block a side change independently for parent, child and mapping references, then delete their parent and assert only direct children become top-level, grandchildren retain their parent, incident mappings disappear, and the warning is visible. `test_circular_fields_and_mapping_controls`: Roots and members have radius but no shape selector; parent and relation choices are restricted by side; adding a mapping defaults to same-position, explicitly switching it submits `samePosition: false`.
- [ ] **Run red.** `python3 tests/browser/interactive_debugger_browser_test.py --directory build-wasm/interactive --phase editor`; expect page or editing assertions to fail. Use the Task 1 test server pattern, serving a test harness in the same local origin without adding production static assets.
- [ ] **Wire editor and scheduling.** Initial case is the spec's 1×1 example. Edit Root radii and the member ID, label, side, parent, radius, rotation, spacing and auto-resize. Keep model shape fields inside a circular dimension control; write text with `textContent`, and never build selectors or markup from raw IDs/labels. Keep incomplete number edits separate from committed numeric data, including export validation. On an accepted ID change update references and selected ID atomically; on deletion clear references and warn without confirmation. Toggle auto-calculate (default on), schedule structural changes immediately once valid, and render `计算中` before entering synchronous WASM. Coalesce timer/manual callbacks using a single pending job and a draft revision; never apply a result to a different revision. Preserve input focus/caret by updating only the affected controls or result pane.
- [ ] **Run green.** Rebuild WASM and run the editor phase; expect all four tests pass and the compiler emits the exact five static assets named in the spec.
